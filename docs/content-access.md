# 文章与局部内容权限

文章的唯一持久化权限字段为 `visibility`：

| 值 | 可读者 |
| --- | --- |
| `public` | 所有人 |
| `members` | 已验证邮箱的会员、管理员 |
| `editors` | 编辑和管理员 |
| `private` | 作者和管理员（作者降为会员仍可阅读，不能再发布或编辑） |

普通会员和游客不能发布或编辑。编辑只管理自己的文章，不能增加/修改可执行 Markdown 或原始 HTML；受限块中的内容也接受同样的检查。

当前数据模型仅使用 `visibility`，不再识别或自动转换 `is_private`。不提供旧数据库的自动兼容迁移，部署边界见 [配置与兼容策略](configuration.md)。

## 局部 Markdown

在 Vditor 工具栏点击锁形“受限内容”，选择读者范围并填写 Markdown。选中的编辑器文本会预填；插入后可在围栏内修改内容及权限。工具自动选择足够长的外层围栏，避免正文里的代码围栏提前结束受限块。

文章编辑器与后台首页的哔哔快速发布共用此工具。哔哔没有另一套权限语法：同样由 Lute 在服务端裁剪，首页、Topic 列表、详情及订阅源都不能输出当前读者无权读取的片段。

````markdown
公开内容。

```access:members
## 会员可以阅读的标题

**Markdown**、列表、表格、引用等正常使用。
```

继续公开内容。
````

支持 `access:members`、`access:editors`、`access:private`。无需公开局部块，普通正文就是公开（但仍受整篇文章权限约束）。

这是 Solitudes 的 Markdown 扩展，不声称是 CommonMark 标准功能。选择标准围栏边界，是因为 Lute 和 Vditor 均原生支持它：Lute 解析出代码块 AST 后，仅处理专用 `access:` 节点，并把块内内容作为独立 Markdown 子树解析。它不会占用普通 `:::`、HTML 注释、引用或代码示例的语法。其他 Markdown 阅读器可能将它显示为代码块；**原始 Markdown 文件本身不是加密文件，不应公开导出受限文章原文**。

嵌套时外层围栏须比内部更长，最多 16 层；权限取各层交集，内层不能绕过外层。未知权限、未闭合受限块拒绝保存；读取异常旧数据时整段正文失败关闭。Lute 块解析阶段检查闭合状态，避免其内联阶段自动补齐闭合围栏掩盖输入错误。

## 防泄露范围与边界

- 权限判断和裁剪在服务端、模板渲染前完成，隐藏正文不发送给浏览器。
- 目录使用 Lute AST，从裁剪后的正文生成；摘要、封面、元数据同样只使用可见内容。
- 共享 RSS/Atom/JSON feed 只输出公开文章的公开正文；站点地图和公开动态不暴露受限文章。
- 搜索仅索引公开正文；受限文章只能由有权读者按标题搜索。旧版本正文不索引；搜索返回前用当前数据库内容再次匹配，防止旧索引片段泄露。不自动改写旧格式索引；旧安装导入后须重建索引，见配置与兼容策略。
- 历史版本沿用最新文章的整体可见性；修改整体可见性会立即影响所有历史版本。版本内的片段按该版本正文中的 `access:` 规则、结合当前读者身份裁剪，不沿用最新版的片段规则。因此，后来才遮蔽的片段，在当时未遮蔽的旧版本里仍对有整篇阅读权限的人可见。历史页禁止搜索引擎索引。
- 登录响应禁止缓存；公共 HTML 要求重新验证，不允许旧正文通过 stale-while-revalidate 继续被分发。
- **上传文件仍是公开静态文件。遮蔽图片/附件链接不会赋予该文件下载权限，也不能撤回其他人已经下载或缓存的公开内容。不要把敏感附件上传到公开媒体库。**

权限不是 DRM；有权读者仍能复制其可见内容。公开评论也不应引用原文中的私密段落。
