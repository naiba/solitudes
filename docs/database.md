# 数据库结构、性能与保留策略

使用 PostgreSQL 存储关系数据，Bleve 提供进程内全文搜索，不依赖 Redis 或独立搜索集群。索引和权限查询与主题无关。

## 结构与一致性

- 用户、文章、文章历史、评论各一张表；角色是用户字段，游客／会员评论共用评论表。
- 会话、邮件操作、第三方身份、WebAuthn 和 OAuth/OIDC 授权分别建模，长期凭据与短期请求独立清理。
- 已授权应用直接由有效访问／刷新令牌及已批准、未消费且未过期的授权请求汇总，不另建授权表、不存重复权限或时间字段。每个分支先按当前用户与有效期过滤，再按应用合并有效权限和最晚到期时间；无有效凭据的历史登录不进入列表。
- 用户撤销授权仅清理自己与该应用的待处理请求、授权码和访问／刷新令牌；拥有者或管理员删除应用则清理该应用全部用户的这些记录，再删除应用。两者均与审计写入处于同一事务。禁用、删除、撤销与令牌签发先锁定应用行，避免已载入请求在撤销后重新签发凭据。撤销的归属检查包含已消费或刚过期的请求，防止并发兑换或页面过期导致无法撤销。审计与登录汇总保留。
- 文章 `slug` 唯一且非空；历史 `(article_id, version)` 联合唯一且非空，不再维护无用途的独立版本索引。
- 角色、文章可见性有数据库 CHECK；认证记录必须引用存在的用户／应用。删除用户或应用时，相关临时凭据级联删除；仍拥有应用／内容的用户不能直接删除。
- 刷新令牌的 `access_id` 不加外键：访问令牌可先过期并回收，不能连带破坏仍有效的刷新令牌。
- 审计和登录汇总不对用户／应用加外键，防止业务对象删除时连带抹掉历史。
- 保留文章／评论的现有外键和数据，不自动删除重复文章或历史来绕过迁移错误。

## 索引和查询

模型负责唯一约束、基础索引与标签 GIN；`MigrateDatabasePolicy` 显式创建当前模型所需的联合／部分索引和约束，不再删除旧版本索引或回填旧业务数据。

| 查询 | 索引／策略 |
|---|---|
| 文章地址、历史版本 | slug 唯一；文章 ID + 版本联合唯一 |
| 标签包含 `@>` | GIN，不再使用数组 B-tree |
| 最新文章、作者文章 | 时间 + ID；作者 + 时间 + ID |
| 专栏章节、阅读／评论总数 | 复用 book_refer 索引；元数据递归 CTE、整页批量 SUM；每层检查可见性 |
| 文章评论／回复 | 文章 + 父评论 + 时间 + ID，仅非垃圾评论 |
| 用户／应用分页 | 时间 + ID；应用拥有者 + 时间 + ID |
| 用户已授权应用 | 复用凭据表的用户索引；合并去重后按应用名 + ID 稳定排序，20+1 分页 |
| 审计分页和清理 | 时间 + ID |
| 用户／应用登录统计 | 成功登录的用户或应用／用户部分索引 |
| 过期认证数据 | expires_at 索引 |

管理列表先执行过滤和分页，再对当前页计算统计。不要在 LIMIT 之前全表聚合，也不要仅把聚合换成关联子查询：OFFSET 跳过的行仍可能触发子查询。执行计划回归会检查第 1 页和第 5 页的统计子计划均至多执行 25 次。

数据库统计仅后台总览缓存 30 秒，并合并并发计算；权限、禁用状态、列表明细、用户／应用详情和审计记录不使用此缓存。首次／缓存失效后的全站精确总数仍需要扫描相关数据，不是 O(1)。姓名／邮箱包含搜索也不保证走 B-tree，暂不为低频管理搜索引入额外索引服务。

另有进程内纯文本摘要 LRU（256 条，每条上限 512 字符的摘要），按已过滤内容的 SHA-256 和长度寻址，不缓存权限、正文或 AST。专栏统计不落冗余表，也不跨请求缓存；详见 [性能测量](performance.md)。

## 配置

在 `data/conf.yml` 中可配置（示例不是自动启用清理的操作）：

```yaml
database_pool:
  max_open: 20
  max_idle: 5
  lifetime_seconds: 1800
  idle_seconds: 300
audit_retention_days: 0
```

连接池零值采用默认值；默认 idle 不大于 max_open。拒绝负数、idle 大于 open 及无效时长。限制是**每进程**的，多副本应给 PostgreSQL 的管理连接和其他应用留出配额。

`audit_retention_days: 0` 永久保留详细审计，正整数显式启用按天保留（最大 36500）。例如设为 90 后，超期 IP、请求 ID、操作详情将**永久删除**，除非管理员另行备份／归档，不能从汇总还原。后台审计页展示当前策略。

## 定时维护

每小时第 17 分钟执行，单次上下文限时 30 秒。每张表每批至多 1000 条、至多 20 批，避免一次积压清理持有超大事务。未清完的记录下次继续。

- 清理已到期的登录会话、邮箱操作、OAuth 尝试、WebAuthn 仪式、OIDC 授权请求和访问／刷新令牌。
- RSS 访问记录保留 7 天。
- 不删除用户、文章、历史、有效令牌、第三方身份、WebAuthn 凭据和服务端密钥。
- 审计清理仅在显式启用保留天数后执行，保留 `audit-initialized` 起始标记。
- 通过 `FOR UPDATE SKIP LOCKED` 分批处理；并发工作者不会重复清理同一批记录。
- 所有清理目标限定当前 schema；本 schema 缺表时失败，不向 search_path 后续 schema 查找同名表。

## 为什么增加一张登录汇总表

`login_summaries` 使用 `(action, client_id, actor_id)` 联合主键，只保留登录次数及最后登录时间，不存 IP、请求详情或令牌。行数随实际用户／应用关系增长，而不是随每次登录增长。没有新增多套用户／应用计数列。

清理时，在同一条 PostgreSQL 语句中删除过期详情并累加汇总；任何汇总写入失败都会回滚删除。统计在同一个查询快照里合并“尚存详情 + 已归档汇总”，保持累计次数、去重登录用户数、最后登录时间不变；同一用户同时存在于新旧数据中只算一个用户。刷新令牌不计作新登录。

汇总不是原始审计归档，无法还原历史安全事件；未启用详细日志清理时，也不会降低日志存储增长。数据库空间回收依赖 PostgreSQL autovacuum；DELETE 通常只让空间可复用，不立即缩小磁盘文件。正常维护不运行阻塞性的 VACUUM FULL。

## 迁移和测试

启动时先执行模型迁移和既有数据回填，再运行显式、可重复的约束／索引迁移。DDL 限定当前 schema，不沿 search_path 删除其他 schema 的同名对象。发现重复 slug／版本、非法角色、孤立引用时失败退出，由管理员检查数据；不会静默丢弃业务记录。

当前仍是启动迁移，不宣称在线零停机：索引构建和约束校验可能持锁，大库应先备份，在维护窗口单实例升级；显式迁移设 5 秒锁等待上限。这一轮没有引入通用迁移框架或分区。

PostgreSQL 测试使用随机独立 schema，结束后仅删除自身 fixture。覆盖唯一性、迁移重入、外键、schema 隔离、过期边界、默认不删审计、并发归档、失败回滚、统计不变、连接池和查询计划。CI 现有 PostgreSQL `go test` 会自动执行新增用例。

查询计划 fixture 包含 5000 用户、5000 应用、20 万审计、1 万文章；检查实际使用索引和分页统计执行次数，并输出执行时间、表及索引大小，不用易受 CI 机器负载影响的毫秒阈值断言。这是单机合成数据回归，不等于生产并发压测或所有查询都已优化。

```bash
SOLITUDES_TEST_POSTGRES_DSN='postgres://postgres@127.0.0.1:5432/solitudes_test?sslmode=disable' \
  go test -tags postgres_test ./... -count=1
```

## 身份与初始化

账户和密码只持久化到 `accounts`；配置文件不存储用户、密码或登录令牌。新安装用本机 `init-admin` 初始化，事务锁保证并发初始化只成功一次。启动及初始化不会修改已有账号、文章作者或文章可见性。评论角色仅通过 `account_id` 关联当前账户计算，不再维护 `is_admin` 副本。兼容边界见 [配置与兼容策略](configuration.md)。
