# 列表分页

分页和权限过滤由后端完成，不依赖主题名称。首页的最新文章、最新评论、活跃会员和用户详情的最近应用属于摘要；完整列表提供独立入口。

| 列表 | 参数 | 每页 |
| --- | --- | --- |
| 文章、书籍、标签下文章 | 路径中的页码 | 20 |
| 标签目录、后台标签管理 | `page` | 50 |
| 搜索 | `w`、`page` | 10 |
| 读者圈会员 | `page` | 12 |
| 公开主页的文章／评论 | `articles_page`／`comments_page` | 各 12 |
| 顶层评论 | `comment_page` | 20 |
| 评论线程的直接回复 | `thread`、`replies_page` | 20 |
| 个人应用 | `page` | 20 |
| 个人已授权的第三方应用 | `page` | 20 |
| 个人 Passkey | `passkeys_page` | 10 |
| 后台文章／评论 | `page` | 20 |
| 后台用户／应用／审计／应用登录用户 | `page` | 25 |
| 后台媒体 | `page` | 15 |

页码缺省为 1；非法、负数、零及超过 1000 的页码返回 400，避免整数溢出和无限深翻页。数据库分页错误向上传递，不当作空列表吞掉。数据库列表使用唯一 ID 作为同值排序的最后一项。

新列表提供 `.Data.navigation`，包含 `Page`、`Previous`、`Next`；链接缺失表示不存在对应页。链接使用站内相对路径，保留筛选参数。评论列表使用 `.Data.comment_navigation`，Passkey 使用 `.Data.passkeys_navigation`。主题可直接渲染这些数据，也可复用各自的 `site/pagination` 或 `admin/pagination` 模板。

评论默认只预览每条顶层评论的前 3 条直接回复。“查看回复”进入独立分页的线程；评论直达链接携带 `thread`，不依赖该评论恰好出现在首页。访问线程仍须通过文章权限、所属文章和祖先评论反垃圾校验。

搜索按稳定排序分批扫描候选并重新校验当前权限、正文及去重，再对有效结果分页；不会把“仅取前 100 条候选”误当完整结果集，也不复用旧索引中可能已被隐藏的正文片段。扫描受 5 秒查询时限约束，取消时不会继续扫描；超时不会伪装成完整的空结果页。

`TestBrowserThemeMatrixPagination` 使用隔离 PostgreSQL 数据和临时媒体目录，在两套主题中点击跨页入口。它匹配现有 CI 的 `-run TestBrowserThemeMatrix`，无需另行启用。
